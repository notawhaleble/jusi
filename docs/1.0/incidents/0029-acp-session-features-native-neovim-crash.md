# Инцидент 0029: Нативное падение Neovim в тесте возможностей сеанса ACP

- Дата: 2026-10-18
- Статус: не решён; отдельные проверки bootstrap проходят

## Наблюдение

При проверке ADR 0051 с соседней рабочей копией `jusi-acp` более широкий сценарий
`test_session_features_through_real_notebook_and_terminal` завершал Neovim
0.11.4 сигналом 11 до записи результата. Повторение исходного сценария
без новых шагов bootstrap и автодополнения воспроизвело падение.
Это не устанавливает причину и не доказывает регрессию bootstrap.

Отчёт macOS указал `EXC_BAD_ACCESS` по адресу `0x10` в главном потоке через
`vim_regexec_string`, `match_file_pat`, `aucmd_next`, `apply_autocmds_group`,
`nvim_exec_autocmds` и запланированный обработчик Lua во время `vim.wait`.
Ошибка Python или трассировка Lua от этого процесса отсутствовали.

## Область и проверки

- Основные тесты Python, headless-фронтенда и сквозные тесты Neovim прошли.
- Сценарий интерфейса вопросов ACP и тесты провайдера GigaCode прошли после
  согласования пути исходников ядра Jusi и статического объявления возможностей
  семейства GigaCode.
- Отдельный `tests/fixtures/bootstrap.lua` ACP проходит с реальными сервисом,
  ядром, рабочим процессом, терминальным приложением и тестовым агентом ACP.
  Он подтверждает сохранение черновика, автодополнение до первого запроса,
  использование того же клиента и отсутствие запроса агенту в событиях.
- Более широкий сценарий возможностей сеанса не изменён. Расследование
  нативного падения отделено от контракта инициализации.

Стенд интерфейса ACP теперь сохраняет явно заданный `PYTHONPATH`, позволяя
выбрать соответствующую рабочую копию ядра вместо неявной загрузки старой
установки. Запускайте с путями актуальных исходников Jusi и GigaCode:

```sh
PYTHONPATH=/path/to/jusi/src:/path/to/jusi-gigacode/src .venv/bin/python -m pytest tests/test_followup_ui.py -q
```

Используйте абсолютные пути в `PYTHONPATH`, если дочерний процесс меняет каталог.
