# Инцидент 0030: Окна веб-вывода и ошибки строки состояния браузера

- Дата: 2026-10-19

Первый запуск matplotlib мог вывести сообщение о кеше шрифтов перед графиком.
Текст создавал терминальное представление, а следующий пакет MIME безусловно
открывал ещё одно окно. Повторные выполнения без сообщения о кеше выглядели
правильно, поскольку создавали только веб-представление.

Теперь веб-вывод выбирает видимое представление той же ячейки в той же вкладке
и открывает буфер хоста в этом окне. Прежний текст и расширенные буферы
принадлежат ячейке до очистки. Последующий потоковый вывод сохраняется
без нового окна. При ошибке восстанавливается прежний буфер; окно с посторонним
содержимым никогда не считается принадлежащим представлению.

Фокусировка управляемого веб-буфера могла вызывать `E121: Undefined variable`
с `[Profile: default | Text ready]`. Выражение `%!` для всей строки состояния
ядра Jusi было несовместимо с добавляемым хостом индикатором `%{...}`:
Neovim разбирал объединённую настройку как Vimscript. Теперь используется
повторно вычисляемый элемент формата `%{%...%}`, а суффиксы сохраняются
при обновлении установленного формата.

Регрессионные тесты охватывают использование окна текста для веба,
последовательный расширенный вывод, сохранение потокового текста, фокус,
вычисление составной строки состояния, откат открытия хоста и полный путь
сервис/ядро/SSE/Neovim. Проверка только для чтения с реальным модулем статуса
браузера `jusi-neovim` прошла при обоих порядках загрузки модулей.
Реальный запуск matplotlib с новым каталогом кеша шрифтов в настроенном
Python 3.13 подтвердил использование исходного текстового окна для PNG.
Сформированный документ JavaScript также проверен в изолированном скрытом
окне Electron.
