# ADR 0052: Вывод в веб-буфер и действия с URL

- Статус: принято
- Дата: 2026-10-18

## Решение

Проверять наличие необязательной команды `JusiWebBuffer` при показе вывода.
Вызывать её со структурированными аргументами `nvim_cmd` в подготовленном окне,
сохранять созданный хостом буфер и оставлять фокус в блокноте при автоматическом
выводе. Хост владеет сеансом браузера; Jusi — идентичностью ячейки и очисткой
представления. Обычное закрытие окна только скрывает вывод. Закрытие или замена
ячейки удаляет все её расширенные буферы и локальные временные файлы.
Несколько выводов сохраняются отдельными представлениями до очистки ячейки.
Новый расширенный вывод использует видимое окно этой ячейки, включая окно
предшествующего текстового вывода. Предыдущий текст остаётся в терминальном
буфере; последующие потоки не заменяют видимый браузер и не создают новое окно.
При ошибке открытия хоста в используемом окне восстанавливается прежний буфер.

Расширенный вывод Jupyter сохраняет варианты MIME в объекте JSON с типом
`application/vnd.jusi.mime-bundle.v1+json`. Каждый упорядоченный фрагмент
содержит `bundle_id` и булев `bundle_end`; только последний завершает пакет.
Сохраняется предел события 16 КиБ UTF-8. Пакет ограничен 16 МиБ UTF-8;
более крупный вывод использует `text/plain` или явное сообщение об ограничении.
Фронтенд накапливает фрагменты по ячейке, декодирует только полный пакет
и отсекает устаревшие идентификаторы выполнения. Чисто текстовый вывод
сохраняет прежнее потоковое представление.

При поддержке веб-буферов фронтенд предпочитает HTML, SVG, PNG, JPEG, GIF,
затем JavaScript. MIME `application/javascript` и `text/javascript`, включая
IPython `%%javascript`, выполняется как ресурс скрипта base64 в отдельном
документе со стандартным контейнером DOM `element`. Среда виджетов Jupyter,
jQuery и мост Python не предоставляются. Ошибки скрипта показываются
в документе как содержимое представления браузера.

Полное содержимое записывается в приватный локальный HTML-файл фронтенда,
открываемый через file URL. Это работает с удалёнными ядрами без общей файловой
системы и преобразования целевых путей в локальные URL. Изображения используют
data URL внутри документа. HTML — браузерное содержимое блокнота,
а не экранированный терминальный текст. Строка состояния ядра Jusi использует
вычисляемый элемент формата, чтобы хост мог добавлять статус браузера,
не расширяя выражение Vimscript для всей строки. Существующие суффиксы
сохраняются при обновлении фокуса. Без команды хоста используется `text/plain`
или явное сообщение о необходимости расширенного средства отображения.
Ошибка создания представления сообщает локальный сбой и сохраняет текстовый
запасной вариант.

Это расширяет ограниченный вывод событий ADR 0018 конечными снимками,
а не транспортом непрерывного содержимого приложения или веб-сервера.
Снимки занимают ограниченные фрагменты сохранённой истории SSE;
это не долговременное хранилище артефактов. Обновления Jupyter display-id
и семантика clear_output пока не входят в реализацию.

## Действие с URL

Общие действия редактора расширяются `open_url` с содержимым
`{action: "open_url", url: "https://…", text: ""}`. Пустой `text` сохраняет
существующее кадрирование снимков, загрузку фрагментов и подтверждение.
URL передаётся приватной загрузкой содержимого, а не упорядоченными метаданными
действий. Допустимы только абсолютные HTTP(S) URL без пробельных и управляющих
символов. Фронтенд не вызывает оболочку и не подставляет строку в Ex-команду.

`jusi.editor_client.open_url(url)` доставляет ссылку через канал
`editor_actions` существующего клиента. `jusi.plugin_api.open_url(url)`
создаёт результат действия редактора для рабочего процесса. Доставка приложения
захватывает и проверяет исходное окно клиента, как открытие текста;
устранение дубликатов после переподключения и подтверждения не меняются.
Созданный веб-буфер — независимый снимок. Отсутствие поддержки хоста завершает
доставку ошибкой без неявного запуска внешнего браузера.

URL должен быть доступен с узла редактора. Ядро Jusi не переписывает loopback
и не создаёт удалённые туннели. Будущему долговременному веб-клиенту нужен
явный контракт поверхности, подключения, аутентификации и жизненного цикла.
Предложение обратного прокси ADR 0017 остаётся отложенным; здесь приняты
только конечный расширенный вывод и общая внешняя навигация.

## Проверка

Общие допустимые и недопустимые фикстуры проверяют схемы и валидацию Python/Lua.
Тесты охватывают подтверждение доставки URL, инъекции команд, отсутствие
средства отображения, запасной вариант, многофрагментный вывод реального ядра,
фокус, скрытие, удаление, очистку локальных файлов и полный путь
сервис/ядро/SSE/Neovim. Headless-тесты заменяют команду хоста;
они не подтверждают отрисовку браузером Electron.
