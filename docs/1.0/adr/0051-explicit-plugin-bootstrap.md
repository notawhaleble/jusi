# ADR 0051: Явная инициализация клиента плагина

- Статус: принято
- Дата: 2026-10-18

## Решение

Семейства плагинов могут объявлять `bootstrap` вместе с `execute`:
инициализацию без отправки содержимого приложения. Все конкретные провайдеры
одного семейства должны согласованно объявлять эту возможность.

`:JusiBootstrap` инициализирует текущую ячейку, используя только магическую
команду первой строки и её аргументы. Черновик, курсор, фокус и история
сохраняются. Выполнение ячейки плагина с пустым или пробельным телом использует
bootstrap, если он поддерживается. Обычная контекстная отправка уже связанной
ячейки остаётся followup; новой семантики пустого followup нет. `JusiExecute`
сохраняет явную замену существующего клиента; чтобы обеспечить наличие клиента
без замены, используйте `JusiBootstrap`. Обычный ввод и автодополнение никогда
не инициализируют ресурсы (ADR 0027).

Существующая HTTP-команда execute принимает необязательный булев `bootstrap`.
Фронтенд отправляет с ним только заголовок. Супервизор также распознаёт пустое
выполнение поддерживающей bootstrap магической команды по авторитетному
каталогу: это охватывает HTTP-клиентов и гонки доставки каталога при запуске.
Явный bootstrap игнорирует тело, даже если его передал другой клиент.
Неподдерживаемый явный запрос завершается `unsupported` до выполнения ядра.

Bootstrap использует существующий последовательный жизненный цикл выполнения
и передачи управления: события выполнения, прерывание, ограниченную по времени
инициализацию, создание рабочего процесса и поверхности, очистку среды.
Новых долговременных состояний ядра или клиента, операций рабочего процесса
и идентификаторов ресурсов нет. Первая инициализация возвращает обычный ответ
выполнения. Повторная возвращает успешную операцию и существующий `client`,
не создавая выполнение и ничего ему не отправляя.

Супервизор приватно сохраняет исходные `(magic, arguments)` клиента.
Повторная инициализация использует ровно один живой, не закрывающийся клиент
с теми же magic и буквальной строкой аргументов. Изменённые аргументы, другая
магическая команда или неоднозначность клиентов приводят к `conflict`;
пользователь должен явно закрыть предыдущий клиент. Параллельные инициализации
последовательны и не создают два клиента для одного совпадающего запроса.
Фронтенд отклоняет дубликат, пока первый запрос ещё ожидает ответа.

## Контракт ядра и провайдера

Зарегистрированная функция IPython cell magic предоставляет вызываемый атрибут
`__jusi_bootstrap_v1__`. Он принимает строку буквальных аргументов без раскрытия
переменных IPython и выдаёт обычную передачу управления конкретному провайдеру.
Целевой адаптер Jupyter вызывает его через
`jusi.kernel_bootstrap.bootstrap(magic_name, arguments)` с литералами Python.
Так обходится запрет пустого тела IPython без фиктивного тела, запроса SQL,
команды оболочки или запроса агенту. Отсутствие обработчика или корректной
передачи управления завершает инициализацию ошибкой, оставляя живое ядро `on`.

Обработчик владеет разрешением псевдонимов, конфигурацией и подготовкой.
Его приватная нагрузка попадает в обычный обработчик `execute` рабочего
процесса, создающий тот же долговременный клиент, что при обычном выполнении.
Провайдер не должен считать это отправкой содержимого. ACP использует пустое
начальное тело: соединение, аутентификация и создание сеанса выполняются,
но запрос агенту не отправляется.

Создание не гарантирует получение всех асинхронных метаданных. Автодополнение
использует доступные провайдеру данные; требования аутентификации и обновления
команд остаются его ответственностью. Повторный bootstrap не перезапускает
сеанс, не повторяет аутентификацию и не ждёт метаданных.

## Проверки

- `tests/backend/unit/test_bootstrap.py`: изоляция тела, параллельные повторы,
  использование обычного клиента, несовпадение заголовков, неподдерживаемые
  запросы, закрытие и повторное создание, изоляция отсутствующей передачи.
- `tests/backend/integration/test_kernel_bootstrap.py`: реальный запрет пустого
  тела IPython, явный обработчик, буквальные аргументы и сохранение живого ядра
  при отсутствии обработчика.
- Общие фикстуры команд и каталога для Python и Lua.
- `tests/frontend/bootstrap_spec.lua`: сохранение черновика, отклонение
  ожидающего дубликата, маршрутизация пустого тела и исключение из истории.
- `tests/e2e/bootstrap_spec.lua`: реальные HTTP, ядро, рабочий процесс,
  терминал, автодополнение до первой отправки, идемпотентность и заполненная ячейка.
- Соседний `jusi-acp/tests/fixtures/bootstrap.lua`: реальное приложение ACP,
  автодополнение до первого запроса агенту, сохранение черновика и повторное
  использование клиента. Сбой более широкого теста возможностей сеанса описан
  в [инциденте 0029](../incidents/0029-acp-session-features-native-neovim-crash.md).

## Поддержка в Shell и SQL

`jusi-shell` использует обычное разрешение оболочки и параметров с пустым телом:
запускает интерактивную оболочку и управляющий канал без отправки команды.

`jusi-sql` помечает приватную нагрузку инициализации как `bootstrap: true`
с пустым `sql`. PostgreSQL и ClickHouse сохраняют флаг при подготовке рабочего
процесса, начинают обычную загрузку метаданных и показывают готовый лист вместо
результата запроса. Явная инициализация обходит прежние фиктивные запросы
провайдеров. Метаданные загружаются асинхронно с сохранением настроек провайдера,
включая возможность отключения загрузки в PostgreSQL. Эти нагрузки принадлежат
плагинам; ядро Jusi не интерпретирует их поля.
